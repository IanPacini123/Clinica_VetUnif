## Metodologia (modo professor, com ritmo ajustado)
- **O usuário escreve todo o código da aplicação.** Claude guia, revisa e explica. Claude só executa limpeza, verificação (build, curl, inspecionar arquivos ou containers) e documentação quando o usuário pede ou quando é preciso para diagnosticar.
- **Ritmo:** passos diretos com trechos prontos para o usuário adaptar e digitar, cada um com um "por quê" curto; menos perguntas socráticas. Ao "confere", Claude revisa o código de verdade (`git status`, os arquivos, o build) e não só a saída colada pelo usuário: no 03, assim foram achados o `'api/sessao'` sem `/` e o static antes dos handlers.
- **Ciclo de cada passo:** trecho com explicação → o usuário digita e roda → "confere?" → Claude revisa → aponta a linha exata, a causa e a lição geral → commit.
- **O ticket é dividido em unidades, primeiro o código local, depois as plataformas.** No 03: banco → seed → login → proteção → web (sessão) → layout → publicação.
- **Quando há uma escolha de escopo**, Claude dá uma recomendação e o usuário escolhe (no 03: telas vazias no menu agora, opção a).
- **Analogias com Java/Hibernate/Spring** funcionam bem.
- **Commit ao fim de cada unidade**, sempre da raiz (`git add -A`), conferindo o `package-lock.json`. Prefixo `feature:` (escolha do usuário; não sugerir `feat:`). O usuário também usa `docs:` e `fix:`.
- **O status do ticket é marcado pelo próprio usuário.**
- **Por quê:** é trabalho de disciplina. O README declara que todo o código foi escrito pelo usuário, com a IA guiando o desenvolvimento e o deploy (trechos de referência, revisão) e ajudando nos layouts das telas.

## Decisões Tomadas
- **Ordem de montagem**: monorepo → Postgres → api → shared → web → compose; cada camada é testada antes da próxima.
- **Entidades entram no seu ticket**: `tutor` e `animal` só têm PK; as colunas vêm no 04/05 e a relação no 05.
- **PK `Int @default(autoincrement())`**: a permissão é checada no back, então um id adivinhável não dá acesso. Candidato a ADR 0005.
- **Tabelas, colunas e enums em minúsculas via `@@map`/`@map`**: evita aspas no SQL; no TS os campos continuam em camelCase.
- **`@unique` no `nomeUsuario` no banco**: só o banco garante unicidade com dois cadastros ao mesmo tempo.
- **`crmv` opcional no banco**: a regra "obrigatório para VETERINARIO" depende do perfil e fica na validação (ticket 07).
- **`bcryptjs`, e não `bcrypt` ou `argon2`**: JS puro, sem compilação nativa na `node:24-slim`; o salt vai dentro do hash.
- **Seed em `src/` e rodando no `CMD`**: o `tsc` compila para `dist/seed.js`; o Render Free não tem shell nem pre-deploy. O `upsert` com `update: {}` torna o seed idempotente e não reseta a senha.
- **`ADMIN_SENHA` vem do ambiente**: o repositório é público. Falha cedo se tiver menos de 8 caracteres.
- **`JWT_SECRET` com falha cedo**, como a `DATABASE_URL`; `expiresIn: '8h'` no registro do plugin, e não em cada `sign`.
- **A mesma mensagem para usuário inexistente e senha errada**: não deixa descobrir quais usuários existem.
- **O teste de `ativo` vem depois da senha, com 403**: a mensagem "inativo" só aparece para quem acertou a senha; a identidade foi confirmada, e o problema é a permissão.
- **`UsuarioSessao` montado campo a campo** no login e na `/api/sessao`: o `senhaHash` não vai para o token, e `iat`/`exp` não vão na resposta.
- **No login, `loginSchema` só checa "não vazio"**: o formato (3 a 30 caracteres, `a-z0-9.`, senha ≥ 8) é validado na criação do usuário.
- **Rotas protegidas por padrão (hook global + lista de públicas)**: uma rota nova já nasce protegida. Uma rota `/api` inexistente responde 401 sem token.
- **`exigirPerfil` como factory no `preHandler`**: roda depois do `onRequest`, quando o `request.user` já existe.
- **Rotas em plugin por recurso (`src/rotas/`)**: o `server.ts` não cresce a cada ticket.
- **Erros só pelo handler central**: a rota lança `ErroHttp`; o handler loga o erro original e responde `{ mensagem }`; o `unknown` é estreitado com `instanceof`/`in`/`typeof`.
- **503 para o banco fora**: dependência indisponível não é erro do cliente.
- **O web valida toda resposta com Zod** pela `api()`, que recebe o schema; `Validador<T>` evita o web depender do `zod` direto.
- **Um único `api()` trata o 401** (limpa a sessão e faz `router.replace` para o login), exceto em `/api/login`, onde o 401 é senha errada.
- **Só o token no localStorage**: o `usuario` é recarregado na `/api/sessao` pelo guard após o F5.
- **Sessão em `ref` de módulo, sem Pinia**: dois valores não justificam uma store.
- **Telas protegidas por padrão no router (`meta.publica` nas exceções)**; quem está logado e abre `/login` vai para a Recepção.
- **O menu e o guard leem a mesma lista `telas`** (`meta.titulo`, `meta.perfis`) e a mesma `podeAcessar`. O guard bloqueia a URL digitada; a barreira real é o 403 da API.
- **Layout como rota pai com filhas de caminho absoluto**: o layout monta uma vez; o `RouterLink` usa `tela.path`; `exact-active-class` porque `/` é prefixo de tudo.
- **Um `<aside>` para desktop e celular**: `fixed` + `-translate-x-full` no celular, `md:static` no desktop; o `watch` na rota fecha o menu.
- **Telas vazias agora para Tutores, Animais e Usuários** (escolha do usuário): o menu fica completo e testável; cada ticket preenche a sua tela.
- **Valores padrão de `JWT_SECRET` e `ADMIN_SENHA` só no compose**: o compose é local; em produção vale a falha cedo.
- **`ADMIN_SENHA` no Render antes do push**: sem ela o seed falha, o health check não passa e o Render mantém a versão anterior.
- **Mesma origem em dev e prod**: proxy `/api` no Vite; em prod, o Fastify serve o Vue (ADR 0004). Sem CORS.
- **Static só se `existsSync(WEB_DIST)`, caminho via `import.meta.url`, fallback para `index.html` só em GET fora de `/api`**: a api roda sem o build do web; o Vue Router em modo history resolve no cliente.
- **`Dockerfile.dev` e `Dockerfile` multi-stage separados**: o runtime de prod começa limpo com `npm ci --omit=dev` e copia só os `dist` (~795 MB).
- **`prisma` e `dotenv` em `dependencies`**: a migration roda na inicialização. O alerta do `effect` no `npm audit --omit=dev` foi aceito: a CLI só roda o `migrate deploy`, sem entrada externa.
- **`migrate deploy && seed && start`**: se uma etapa falhar, o servidor não sobe; as duas primeiras são idempotentes.
- **Neon e Render em Ohio, URL direta do Neon**: latência api↔banco de 1–2 ms; o PgBouncer em modo transaction atrapalha os locks do `migrate deploy`.
- **tsx no dev, tsc/vue-tsc no build**: o dev não checa tipos; o build roda antes de commitar e antes do `docker build`.
- **ES Modules** (`"type": "module"` + `nodenext`): imports relativos com `.js` na api; `await` no topo é permitido.
- **Variáveis vêm do ambiente**: `--env-file-if-exists` no dev (no container não há `.env`); `environment` no compose; painel no Render.
- **TypeScript 6 no web e 7 na api/shared**: o `vue-tsc` ainda depende do 6. **npm em vez de pnpm.**
- **CPF e telefone guardados só com dígitos** (o schema faz `transform` antes de validar): `123.456.789-09` e `12345678909` viram o mesmo valor, e o `@unique` pega a repetição. A máscara é só exibição (`formatos.ts`).
- **409 pelo `@unique` (`P2002`), sem consulta antes**: consultar e depois inserir deixa uma janela de concorrência. Só depois do `P2002` a api consulta o dono do CPF; se estiver inativo, a mensagem é `CPF_DE_TUTOR_INATIVO`.
- **`CPF_DE_TUTOR_INATIVO` no shared, comparada no web**: o formulário de Tutor mostra ao ADMIN o link `/tutores?busca=<cpf>&inativos=true` sem mudar o `erroSchema`.
- **E-mail vazio vira `null`** (`preprocess` no schema, `?? null` no `lerTutor`): no `update` do Prisma, `undefined` quer dizer "não mexa", e `null` apaga.
- **Busca**: nome com `contains` + `mode: 'insensitive'` (`ILIKE`); o CPF só entra no `OR` se a busca tiver dígitos. Sem `unaccent` (escolha do usuário: complexidade desnecessária).
- **`$transaction([findMany, count])`** e `orderBy: [{ nome }, { id }]`: o total bate com os itens, e o `id` desempata nomes iguais entre as páginas.
- **Registro inativo responde 404** no PUT e no DELETE, e no detalhe para quem não é ADMIN (`findFirst`/`update` com `ativo: true`): fora do ADMIN, o inativo não existe.
- **`DELETE` = inativar** (ADR 0001); **reativar = `POST /:id/reativar`**, só ADMIN, sem confirmação (não apaga nada) e idempotente (`update` com `where: { id }`).
- **"Mostrar inativos" traz ativos e inativos**, com os inativos em cinza e o selo `SeloInativo`; fora do ADMIN, `inativos=true` dá 403 na api, e o web ignora o `?inativos=true` digitado na URL.
- **O ADMIN vê os inativos nos detalhes sem o filtro**: abre um Tutor ou Animal inativo, e o detalhe do Tutor lista também os animais inativos (depois dos ativos).
- **Um inativo não é editado**: no detalhe, somem "Editar", "Inativar" e "Adicionar animal", e aparece o painel com "Reativar"; o PUT continua dando 404. Primeiro reativa, depois edita.
- **Reativar um Animal exige o Tutor ativo** (`findUnique` com `comTutor` → 409): a mesma regra do POST/PUT. A janela de concorrência com inativar o Tutor ao mesmo tempo foi aceita.
- **`z.stringbool()` no `inativos`**: aceita `true`/`false`/`1`/`0` vindos da query; o `z.coerce.boolean()` daria `true` para `"false"`.
- **`camposDoErro` e `idSchema` no shared**: a api não tem o `zod` nas dependências (evita dependência fantasma), e o web reusa a mesma função.
- **Busca e página na URL** (`/tutores?busca=&pagina=`), com `watch(route.query, { immediate: true })`: o F5, o Voltar e um link copiado mantêm o resultado. Uma busca nova volta para a página 1.
- **Formulário único para criar e editar**, com o mesmo `tutorEntradaSchema` da rota, `novalidate` e os `campos` da API no campo certo; envia `dados.data` normalizado. Depois de salvar, vai para o detalhe.
- **Confirmação da inativação dentro da página** (painel `role="alertdialog"`), e não `confirm()`: segue o visual e funciona no celular.
- **O nome na lista é um `RouterLink`** para o detalhe, e não um clique na linha: funcionam o Tab, o Enter e o "abrir em nova aba".
- **`PODE_CRIAR_E_INATIVAR` em `perfis.ts`**: o router, o botão "Novo tutor" e o botão "Inativar" usam a mesma lista. O PUT fica aberto aos três perfis (a tabela da especificação).
- **Enums `Especie` e `Sexo` sem acento** (`FEMEA`), como o `Perfil`: um identificador de enum não aceita `Fêmea`. O texto de exibição fica em `NOME_ESPECIE` e `NOME_SEXO`.
- **`@db.Date` e a API responde só `AAAA-MM-DD`**: o nascimento não tem hora; um `timestamp` mudaria o dia por causa do fuso. A tela formata a string (`formatarData`) sem passar por `Date`.
- **`hojeLocal()` no shared para "não pode ser futura"**: o web (UTC-3) é mais rígido que o servidor (UTC), então o servidor nunca recusa uma data que o web aceitou.
- **`@@index([tutorId])`**: o Postgres não indexa FK sozinho; o detalhe do Tutor e o bloqueio da inativação consultam por `tutorId`.
- **O Tutor vem embutido na resposta do Animal** (`include: comTutor`): a lista e o detalhe mostram o nome sem uma segunda chamada.
- **Tutor inexistente ou inativo no POST/PUT de Animal → 409 com `campos.tutorId`**: é regra de negócio, e a mensagem aparece na seção do Tutor no formulário.
- **Bloqueio da inativação do Tutor por `count` antes do `update`**: precisa distinguir o 409 do 404. A janela de concorrência (inativar o tutor enquanto alguém cadastra um animal para ele) foi aceita.
- **`GET /api/tutores/:id/animais` sem paginação**: um tutor tem poucos animais.
- **`SeletorTutor` fora do `<form>` do animal**: HTML não aceita form dentro de form; o seletor tem os forms próprios de busca e de cadastro rápido.
- **"Cadastrar novo tutor" escondido para o VETERINARIO, "Trocar tutor" liberado**: ele edita o Animal (inclusive o tutor), mas não cria Tutor.
- **ADMIN em `rotasUsuarios` por hook do plugin** (`addHook('preHandler', ...)`, sem `fastify-plugin`): o encapsulamento aplica o hook só às rotas do plugin, e uma rota de usuário nova já nasce restrita.
- **`omit: semSenha` em toda consulta que responde Usuário**: o `Promise<Usuario>` da rota não remove o `senhaHash`.
- **Nova senha em rota e painel próprios** (`PUT /:id/senha`), e não um campo opcional na edição: editar o nome não mexe na senha, e o campo nunca significa "vazio = manter".
- **O ADMIN não muda o próprio perfil (409)**, como não inativa a si mesmo: evita a clínica ficar sem ADMIN. Na tela, o select fica `disabled` e o "Inativar" some para ele mesmo.
- **Lista de Usuários igual à de Tutores** (escolha do usuário): busca, página e "Mostrar inativos"; a tela toda é do ADMIN, então o filtro não tem outra checagem.
- **`nomeUsuario` imutável pelo schema**: o `usuarioEdicaoSchema` não tem o campo e o Zod descarta a chave; na edição a tela só exibe o valor.
- **Maiúsculas no `nomeUsuario` são recusadas, não convertidas**: o login compara o texto exato.
- **`crmv` vira `null` fora do VETERINARIO** (`crmvDoPerfil` na api): o schema só valida, a normalização fica na rota, como o `?? null` do Tutor.
- **Usuário inativo não é editado nem recebe nova senha** (404, `where: { id, ativo: true }`); o reativar é idempotente e sem confirmação, como no Tutor.
- **"1 Atendimento em aberto por Animal" por índice único parcial**: só o banco garante a regra com duas Chegadas ao mesmo tempo (testado: 3 POSTs simultâneos → um 201, dois 409). O `P2002` vira 409, sem consulta antes, como o CPF. `FINALIZADO` e `CANCELADO` ficam fora do índice, então o Histórico pode ter vários.
- **`@@index([animalId])` além do índice parcial**: o parcial só cobre os Atendimentos em aberto; o Histórico (ticket 10) consulta todos.
- **`onDelete: Restrict` no veterinário**: numa relação opcional o padrão do Prisma é `SET NULL`, que tiraria o veterinário do prontuário.
- **`peso` em `Decimal(5, 2)`**: valor exato até 999,99 kg; o `Float` erra em casas decimais. O Prisma devolve um objeto `Decimal`.
- **Datas do Atendimento em `timestamp`, gravadas em UTC**: aqui a hora importa (ao contrário do nascimento, `@db.Date`). A API responde ISO e a tela formata no horário local (`formatarHora`).
- **Fila = filtro por `STATUS_EM_ABERTO`, sem entidade extra e sem paginação**: a Fila de uma clínica pequena é curta.
- **`STATUS_EM_ABERTO` no shared**: `animais.ts` (bloqueio do DELETE) e `atendimentos.ts` usam a lista; exportá-la de `atendimentos.ts` criaria import circular com o `comTutor` de `animais.ts`.
- **Editar e cancelar: `findUnique` antes (404 ou 409) e `update` com `status: 'AGUARDANDO'` no `where`**: se um VETERINARIO pegar o Paciente entre a leitura e a gravação, o `P2025` vira 409.
- **Cancelar = `CANCELADO` + `dataFim`**: o Atendimento nunca é excluído (prontuário).
- **Prioridade e Queixa editáveis só por ADMIN e ATENDENTE**, como Chegada e cancelamento (tabela de permissões).
- **O veterinário sai só com `{ id, nome }`** (`select`): o `senhaHash` nunca entra na resposta.
- **Bloqueio da inativação do Animal por `count` dos em aberto antes do `update`**: distingue o 409 do 404, como no Tutor.

## Armadilhas Conhecidas
- **`-D` vale para o comando inteiro**; **flag com erro de digitação é ignorada só com um aviso** (`--saved-prod`). Confira o `package.json` depois de cada install; `npm install --save-prod <pkg>` move para dependencies.
- **A tag `latest` do `prisma` é `8.0.0-rc`**: use `prisma@7` e `@prisma/client@7`. A fonte da verdade é `npx prisma --help`, não docs de outra versão.
- **O `prisma init` gera extras** (skills de IA, `.env` `prisma+postgres://`): olhe o `git status` depois de qualquer gerador.
- **O Prisma 7 não lê o `.env` sozinho**, e o `migrate dev` não roda o `generate`.
- **`` `${process.env.X}` `` transforma `undefined` em `"undefined"`**; variáveis de ambiente são `string | undefined`: `Number(x ?? padrão)`.
- **Sem `include`, o `tsc` compila tudo da pasta**; `tsc arquivo.ts` ignora o tsconfig; `tsc` só compila, `tsx` executa.
- **Interpolação `${}` só com crase**; barra invertida em script do package.json quebra o JSON.
- **`localhost` dentro de um container é o próprio container**: use o nome do serviço (`db:5432`, `api:3000`) ou `host.docker.internal`. O servidor em container precisa ouvir em `0.0.0.0`.
- **`POSTGRES_*` só vale na primeira inicialização do volume**; `$${VAR}` no compose deixa a variável para o shell do container.
- **`git add .` só pega a pasta atual**: use `git add -A` da raiz. **Nunca editar `src/generated/`.**
- **Erros de digitação que falham em silêncio**: `felx` (Tailwind), `nodde_modules` (`.dockerignore`), `<script setur>` (o Vue trata como `<script>` comum; o template não enxerga nada e o botão não faz nada). Quando tudo do script aparece como inexistente no `vue-tsc`, o problema é a tag.
- **`catch` genérico engole qualquer erro** (`saudeSchemaparse`): faça log no `catch` e rode o build.
- **O parser aponta onde percebeu o erro, não onde ele está**: `import fastifyStaticfrom` → `TS1005`; `name 'login'` sem `:` → "`,` or `}` expected". Olhe o token anterior.
- **Import de tipo sem `type` quebra só no `tsx`** (`does not provide an export named 'RespostaLogin'`): o que vem de `z.infer` é importado com `type`; o `*Schema`, sem. O `verbatimModuleSyntax` do build acusa (`TS1484`).
- **Editar o `src/` do shared não muda nada até o `npm run build -w @clinica/shared`**: os consumidores leem o `dist` (`does not provide an export named 'loginSchema'`).
- **No Fastify, uma rota guarda o error handler e os hooks que existiam quando foi registrada**: `await register(plugin)` antes do `setErrorHandler` deu o corpo padrão `{statusCode,error,message}`. Configure handlers e hooks antes dos `register`.
- **O `Promise<T>` da rota não remove campos**: `return request.user` mandou `iat` e `exp`.
- **Container esquecido na mesma porta**: o `docker run` do ticket 02 (`boring_engelbart`) ficou 5 h na 3000, e a rota nova deu 404. No Windows os dois fazem bind sem `EADDRINUSE`. Diagnóstico: `netstat -ano | findstr :3000` e `docker ps`; use `--name` e pare o container.
- **`fetch` sem `/` inicial é relativo à página**: `'api/sessao'` funciona em `/` e vira `/tutores/api/sessao` em `/tutores` (o fallback devolve HTML com 200).
- **O perfil fica dentro do token**: depois de mudar o perfil no banco, saia e entre de novo para testar.
- **`erasableSyntaxOnly` no web**: sem *parameter properties* (`constructor(public status...)`); declare o campo.
- **Docker e plataformas**: erro de compilação no `docker build` custa ~30 s (o build local, ~2 s); o Dockerfile de produção se chama `Dockerfile` (outro nome exige `-f`); a região do Neon não muda depois de criado; não criar `PORT` no Render; a URL do Neon e a `ADMIN_SENHA` de produção ficam só no painel do Render.
- **No `create-vite`, o `@types/node` vem na versão mais nova**: alinhe com `@24`. **`rm -rf` de caminho errado não dá erro.**
- **O error handler do Fastify recebe `unknown`**: estreite antes de ler `statusCode`.
- **`exactOptionalPropertyTypes` na api** (o web não usa): `x?: T` quer dizer "a chave pode faltar", não "pode valer `undefined`". Atribuir um `T | undefined` num campo de classe dá `TS2412` (use `x: T | undefined`); um `email?: ... | undefined` no `data` do Prisma dá `TS2375`.
- **A anotação de retorno vence a inferência**: `lerTutor(): TutorEntrada` "esqueceu" o `?? null` do corpo. Quando a função normaliza, o tipo de saída mostra a normalização (`DadosTutor`).
- **Arquivo não salvo no editor**: o `tsc` compila o que está em disco, e o build passa com o código antigo. Confira o `git status`.
- **Trecho colado com linhas cortadas ou com placeholder** (`// ... igual ao passo 4`): dezenas de `',' expected` seguidos vêm de um erro só; olhe o fim das linhas coladas a partir do primeiro erro.
- **`contains: ""` casa com tudo**: a busca `"ana"` vira `""` no `soDigitos` e devolveria a tabela inteira.
- **Inserts recusados (409) gastam ids da sequência**: o tutor seguinte pode vir com o id 7 em vez do 4; é normal.
- **O Vue reaproveita a instância ao trocar entre rotas do mesmo componente** (`/tutores/novo` ↔ `/tutores/:id/editar`): use `watch(id, carregar, { immediate: true })` com o reset no começo, e não só o `onMounted`.
- **`route.query.x` pode ser string, `null` ou array**: reduza com `typeof valor === 'string'`.
- **O `watch(id)` dispara ao sair da tela**: ao ir do formulário para `/animais/:id`, o `route.params.id` muda antes de a tela desmontar, e o `carregar` buscaria de novo. Comece o `carregar` com `if (route.name !== '...') return`.
- **HTML não aceita `<form>` dentro de `<form>`**: o navegador descarta o form interno, e o Enter na busca enviaria o form de fora. Deixe as seções com form próprio fora do form principal.
- **`@db.Date` lido pelo Prisma vira `Date` à meia-noite UTC**: `new Date('2020-05-01')` também é UTC, então ida e volta batem; formatar com `toLocaleDateString` no Brasil (UTC-3) mostraria 30/04. Use `toISOString().slice(0, 10)` na api e formate a string na tela.
- **curl com `Content-Type: application/json` e sem corpo dá 400 no Fastify** (`requisição inválida`, no `DELETE`): não é bug da rota; a `api()` do web só manda o header quando há `body`.
- **Migration que cria coluna `NOT NULL` sem valor padrão só roda com a tabela vazia**: confira a contagem no local e no Neon antes do push.
- **`z.coerce.boolean()` em query string**: `Boolean("false")` é `true`, então `?inativos=false` ligaria o filtro. Use `z.stringbool()`, que recusa valores fora de `true`/`false`/`1`/`0`/`yes`/`no`/etc. com 400.
- **Schema Zod com `.refine` não aceita `.extend`**: monte a base sem o refine (`usuarioCampos`) e aplique o refine em cada schema derivado.
- **No Zod 4, o `.refine` do objeto roda mesmo com erro nos campos**: o erro do CRMV aparece junto com os outros, sem esperar a correção.
- **O Prisma não aceita os argumentos de um atributo em várias linhas** (`This line is not a valid field or attribute definition`): `@relation(...)` e `@@unique(...)` ficam numa linha só, mesmo longa.
- **O Postgres reescreve o `WHERE` de um índice parcial** (`status IN ('A', 'B')` vira `(status = ANY (ARRAY['A'::status_atendimento, ...]))`), e o Prisma compara o texto: com o texto original no schema, toda migration nova tentaria apagar e recriar o índice. Use o texto do `npx prisma db pull --print` e confira com o `migrate diff --from-config-datasource`.
- **Renomear um export do shared quebra os consumidores**: a troca no web vai no mesmo commit do shared (`git add` com os caminhos, e não `-A`); senão, aquele commit não compila.
- **Uma rota `/api` inexistente também responde 401 sem token**: para saber se a rota nova existe, teste com token.
- **Produção sem o código novo**: commits locais sem push (`git status -sb` mostra `ahead N`), e o Render só faz deploy no push. Para conferir o que está publicado, procure a rota nova no `assets/index-*.js` da URL pública.
- **O nome da pasta da migration define a ordem num banco vazio**: a `…103445_atendimento_um_por_veterinario` vinha antes da `…120019_cria_atendimento` e, num banco novo, criava o índice antes da tabela. Local e Neon não acusavam porque aplicaram na ordem de criação. Teste o `migrate deploy` num banco novo (`seed_teste`).
- **Renomear uma migration já aplicada quebra o deploy** sem o `UPDATE` do `migration_name` no `_prisma_migrations` de cada banco: o Prisma tentaria aplicá-la de novo.
- **`| tail` depois do `migrate deploy` escondeu a falha**: a migration quebrada só apareceu sem o filtro. Confira o código de saída ou a mensagem `All migrations have been successfully applied.`
